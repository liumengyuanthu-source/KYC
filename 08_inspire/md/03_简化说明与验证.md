# Workshop 简化说明与验证

日期：2026-09-09。审查对象是当前新版 Studio，而不是目录中仍保留的早期角色旅程模块。截图来自本次运行中的本地页面；默认浏览器视口为 1280 × 720。

## 1. 为什么原页面不适合作为默认主讲材料

原型有很好的统一案例、五阶段主线和跨团队业务关系。问题是它同时承担了业务讲解、角色矩阵、逐项流程、需求追溯和产品演示等用途，参与者必须先学会界面，才能开始讨论业务。

| 审查步骤 | 观察 | Workshop 影响 | 处理 |
| --- | --- | --- | --- |
| 1. 打开旅程首页 | 顶部有两层导航；案例图之后还有多种图例 | 第一屏难以明确应从哪里开始、要讨论什么 | 入口只保留 Workshop 与参考资料，案例压缩为一段共同背景 |
| 2. 浏览角色矩阵 | 9 个角色、大量重复场景卡与空白格；需要纵向和横向寻找 | 讲解容易跟随页面位置而非案例逻辑，后期阶段不在当前视野 | 默认改为五阶段导航，一次集中讲一个阶段 |
| 3. 打开主体与授权场景 | 流程图、现状 / 目标切换、图例、缩放、章节、编号与展开项同时出现 | 参与者容易陷入操作或实现细节 | 详细流程保留为按需参考，主讲页直接并列痛点与改善 |

截图也显示小号说明文字、细线和复杂图例在投屏时可能难读。该结论基于可见界面，不等于已经完成读屏软件或全套无障碍认证。

## 2. 主讲页面删减了什么

“删减”指从默认讲解界面移走不必要的展示元素，不是删除必要的业务检查或改写源需求。

| 原来的元素 | 本次处理 | 原因 |
| --- | --- | --- |
| 产品、研究、主线、场景索引、流程全集、评分工作坊等并列入口 | 移入“参考资料”视图 | 主讲时只需知道当前讨论阶段 |
| 全量角色泳道和重复头像 | 每阶段只列参与岗位 | 保留责任语境，减少重复信息 |
| 跨列、跨行的大矩阵 | 五个阶段按钮 + 单阶段内容区 | 无需横向找阶段，便于主持人按顺序推进 |
| 源步骤编号、工作项 ID、执行类型和痛点强度标记 | 移到完整场景 / 追溯文档 | 不要求参会者先理解编码与技术分类 |
| 现状 / 目标的多次切换 | 同屏呈现“现在的难点 / 希望怎样改善” | 对比可直接阅读，不必记住上一屏 |
| 每个场景的大图、缩放、章节和多层展开 | 主讲页不展示，按需打开详细场景 | 保持讨论集中在业务问题与产出 |
| 反复出现的技术限定文案 | 归纳为具体的人工判断与案例边界 | 保留关键含义，减少重复说明 |
| 精细评分作为主讲路径 | 主路径使用三项记录：共识、待确认、下一步 | 先形成可验证的结论，再按需要进行优先级评估 |

新增的内容很有限：每阶段一个讨论问题、一个具体案例解释、一组可折叠的记录字段，以及最终汇总与导出。记录和参考区默认折叠。

## 3. 保留的核心业务内容

- 同一个 A / B / T 合成案例以及所有 15 个详细场景入口。
- 主体、关系、身份与代表权限的区别。
- 要求适用性、证据版本及按用途的充分性判断。
- 筛查补件回路和风险专家的裁定。
- 从受理开始的利益冲突检查，信贷与法务并行准备及版本依赖。
- QA、整体就绪、授权确认与发布分别处理。
- 原始 94 项工作与 229 个细分动作的目录和来源关系。

本次没有调整案件引擎、批准规则或实际业务状态；新增讲解模块不调用业务写入操作。讨论记录使用独立浏览器存储键。

## 5. 验证记录

### 已执行

- 本地 HTTP 页面实际加载；首屏不再显示原来的完整角色矩阵。
- 五阶段逐项切换，并检查各阶段标题、人工判断、产出与讨论问题。
- 同一阶段的临时记录在切换、换语言和刷新后仍可恢复；不同阶段的输入不串位。测试记录已清空。
- 中文与英文内容切换，记录内容保留原文。
- 从讲解页打开“整体就绪”完整场景，再收起详情返回讲解。
- 从“参考资料”进入完整矩阵，再返回 Workshop；用 Enter 键切换回第一阶段。
- 独立讲解页实际点击导出；已读取浏览器下载的 Markdown 文件，确认包含 5 个阶段、15 个空白记录位置且没有遗留测试文字。该文件同时保存为 [讨论记录模板](05_Workshop讨论记录模板.md)。
- 用 Node 的隔离测试验证：15 场景覆盖、输入显示转义、阶段记录隔离、越界导航不生效、五阶段导出内容、原业务存储不受影响、浏览器存储失败时仍可导出本页记录、中英文输出。

### 验证范围

这次验证针对 workshop 讲解与记录流程，不是对全部 229 个细分动作、真实银行接口或业务控制的端到端验收。原完整场景中的源内容和既有翻译问题没有逐项重写。

当前截图检查覆盖桌面浏览器。布局包含窄屏适配，但没有做完整手机浏览器和读屏软件兼容性认证；投屏建议使用桌面窗口。1280 × 720 下完整首屏可见案例、五阶段和主要内容，查看底部记录区需要纵向滚动。

打印使用浏览器打印功能与专用样式；本次没有实际连接打印机或逐页核对打印输出。
