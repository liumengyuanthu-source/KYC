# Clear to Trade — UX/UI Design System

**版本：** v1.0 · 2026-09-08  
**用途：** 两个工作任务共享的设计规范：Persona / Journey 内容编排，以及 Studio Before / After 视觉整合；同时约束后续 Product 与 Research。  
**状态：** 汇总用户已确认的方向，并提供可实施的设计细化。不是银行品牌手册，也不代表所有规范已在代码中实现或通过验收。

## 1. 设计定位与优先级

**安静、清晰、有层次的机构业务工作室。黑蓝白为主，暖灰环境，有限使用有厚度感的玻璃表面。**

Macquarie 是用户指定的字体与色彩气质参考，不声称采用其官方字体、品牌资产或官方 Design System。PHKL 是人物、场景图片与操作入口相连接的体验参考，不继承其业务规则。

设计优先级：业务语义正确 → 内容与操作可理解 → 阅读与无障碍 → 层级与一致性 → 材质与动效。

### 已确认、必须遵守

- 三个一级 Tab：**旅程 / 场景工作室、产品原型、Research**。
- 唯一主线：**New institutional onboarding**，不混入持续监控、退出或其他 Trigger。
- Studio 首个主要部分展示已有 Round1 Before / After 流程，默认可见。
- Journey 以角色体验为主，Process 在 Journey 下方提供依据；场景由角色、流程时刻和具体工作推导。
- 每个 Persona 有名字、画像、基础分析、痛点与期待；每个场景有情境图片。
- 同一 Hero case 贯穿场景与产品；合成名字和图像不冒充真实人员。
- Before / After 使用一致图例，明确保留、删除、增强、新增。
- 黑、蓝、白与暖灰；**禁止紫罗兰、薄荷青、粉紫虹彩及大面积强霓虹**。
- 文字和图标清晰稳定；编号与技术信息次级，但重要业务限制不能弱化。
- 播放、图片、聚焦、切 Tab 与返回不写业务状态。

### 本文的数值状态

以下标为“现有”的值来自当前源码；字号、间距、组件尺寸等“规范目标”是本版设计细化，实施时需实际验证。不得把规范目标描述为已完成效果。

## 2. 信息架构与页面层级

| 一级区域 | 主内容 | 不承担 |
|---|---|---|
| Journey / Scenario Studio | Before/After 流程、角色 Journey、场景、Pain/Opportunity、Hero case、D4 分工、对应产品设计 | 实际批准、权限变更或偷偷加载成功结局 |
| Product Prototype | 案件、任务、证据、字段、受控动作、业务结果与回执 | 方法论讲堂、Agent 目录、批次导航 |
| Research | 公司背景、部门、客户旅程、CTT 启发、本次采用位置，附来源与证据类型 | 源码清单、未经核验的供应商宣传墙 |

全局只有上述三个一级入口。References / 来源作为内容级入口，不再与 Research 混同。Operating Model 保留为 Studio 内的深入视角。

### Studio 的固定阅读顺序

1. 简洁标题与 New institutional onboarding / Hero case 定位。
2. **Before / After Process Map**，带统一 legend 和选择详情。
3. 五阶段 Role-based Journey；每阶段下显示关联 Process。
4. 人物与场景的图片化入口；选择后展开完整讨论内容。
5. 精确映射的产品设计图、真实任务入口和 Research 参考。

五阶段为 Initiate / Determine / Assess / Resolve / Clear。M0/M1、M2/M3、M4/M5、M6/M7、M8 是主要锚点，不是强制执行顺序。M7 可由 M1 早启，Legal C1 / Credit C2 的并行关系必须保留。

## 3. 颜色与语义 Token

### 3.1 基础色板

| Token | 值 | 来源 / 用途 |
|---|---|---|
| `color.text.primary` | `#17191C` | 现有 `--ink`；标题、正文、关键数值 |
| `color.text.secondary` | `#5B6067` | 现有 `--muted`；辅助描述和可读的来源信息 |
| `color.action.primary` | `#086BB5` | 现有 `--blue`；主动作、选中边界 |
| `color.action.strong` | `#004D86` | 现有 `--deep-blue`；链接、强调文字、强蓝面 |
| `color.canvas` | `#EFEDE9` | 现有 `--paper`；暖米灰环境 |
| `color.environment.cool` | `#BBC9D6` | 现有背景；右上低饱和蓝灰环境色 |
| `color.surface.solid` | `#FFFFFF` | 实色内容、证据、输入和打印 |
| `color.surface.glass` | `rgba(255,255,255,.53)` | 现有 `--panel`；仅外层玻璃基础 |
| `color.border.subtle` | `rgba(89,103,121,.19)` | 现有 `--line`；非关键分隔 |
| `color.border.control` | `#7A8490` | 规范目标；需清晰识别的控件边界 |
| `color.focus` | `#07558F` | 现有焦点色；浅色面上的焦点轮廓 |
| `color.surface.selected` | `#EAF2F8` | 规范目标；浅蓝选中内容面 |

不把页面整体染蓝：黑色负责信息，白色负责工作，暖灰负责环境，蓝色负责操作与变化。透明面上的文字对比须按实际合成背景检查，不能只比较 token 色值。

### 3.2 色彩不得混用的语义

- 蓝色选中 ≠ 任务完成。
- 蓝色增强 ≠ AI 执行。
- 灰色未知 ≠ 不适用。
- 深色受阻 ≠ 全案暂停。
- 本项完成 ≠ Clear-to-Trade。

不强制用红绿表达业务状态。所有状态必须有文字和一致图标；灰度打印仍能区分。错误使用深色强调、明确文案与边界，不以微弱灰字隐藏。

## 4. 字体、字号与可读性

### 4.1 字体

沿用当前本地字体栈，不新增未经确认的付费字体或远程字体依赖：

```css
font-family: "Helvetica Neue", Helvetica, Arial,
  "PingFang SC", "Microsoft YaHei", sans-serif;
```

字体以清晰的无衬线为主。正文不使用细体；中文不加英文式宽字距。实际使用的字体因系统可用性不同而变化，不能保证所有设备均渲染 Helvetica Neue。

### 4.2 字号规范目标

| 用途 | 桌面 | 窄屏 | 字重 / 行高 |
|---|---|---|---|
| Studio 页面标题 | 36–40px | 28–32px | 400 / 1.2 |
| Product 任务标题 | 28px | 24px | 500 / 1.25 |
| 章节标题 | 24px | 22px | 500 / 1.3 |
| Persona / 场景卡标题 | 18–20px | 18px | 500–600 / 1.35 |
| 正文、表单值 | 16px | 16px | 400 / 1.55–1.7 |
| 数据表、控件标签 | 14–15px | 14–16px | 400–500 / 1.5 |
| 辅助说明 | 14px | 14px | 400 / 1.5 |
| ID、版本、技术追溯 | 12–13px | 12–13px | 400 / 1.5 |

禁止用 10–11px 承载正常业务正文、按钮文案、错误原因或必要证据。字段值和引用允许换行；不要将整张长流程图缩小到文字无法阅读。

英文长文建议控制在约 65–75 字符行宽；中文解释段落保持适度行长。计时和数值可使用等宽数字，但不把整站变成代码字体。

### 4.3 信息优先级

业务标题 → 当前问题 / 目标 → 状态与下一动作 → 必要依据 → 补充说明 → ID / 源码定位。

`SCN-MATCH` 等 ID 不作为主标题。使用“筛查复核”，需要时在下方次级显示 ID。权限不足、资料不可用、版本过时、未保存和真实影响不属于可弱化的技术文字。

## 5. 间距、布局与形体

采用 4px 基础间距：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`。

| 项目 | 规范目标 |
|---|---|
| 页面最大内容宽度 | 1660px，沿用当前主框架；阅读段落另限宽 |
| 页面左右留白 | 桌面 32–48px；平板 24px；手机 16–20px |
| 顶部导航 | 常规约 72–76px；桌面避免多层换行导航 |
| 外层面板圆角 | 30px，现有 `--radius-panel` |
| 内容卡圆角 | 22px，现有 `--radius-card` |
| 输入圆角 | 12–16px |
| 按钮 / Segmented 圆角 | 胶囊形，现有 `--radius-control: 999px` |
| 内容面板内边距 | 桌面 24–32px；窄屏 16–20px |
| 图表节点圆角 | 复用 Round1 / Archify 既有几何，不强行全部胶囊化 |
| 关键交互触控目标 | 至少 44 × 44px；小图标用外层命中区补足 |

圆角表达对象类型，不用每个嵌套区块都加卡片。章节可使用留白和细分隔；避免“卡片套卡片套卡片”。

### 布局模式

- **Studio 流程：** 宽画布 + 就地详情；默认先看流程，不先看一屏介绍。
- **Journey：** 横向阶段、纵向角色；固定的阶段/角色定位不能遮挡实际内容。
- **Scenario：** 中央大面板，顶部定位，主体 Before/After 与图像，字段按需展开。
- **Product：** 必要依据约 2/3，当前行动约 1/3；窄屏依据在前、行动在后。
- **Research：** 图片/公司语境与统一案例结构；不采用随机长度的宣传卡墙。

## 6. 玻璃材质与空间层级

### 6.1 三层空间

| 层级 | 材质 | 用途 |
|---|---|---|
| 外层面板 | 半透明、乳白雾感，有限 backdrop blur | Studio 容器、轻量工具栏 |
| 内容卡片 | 更实、更安静，白或近实色 | 场景、Persona、解释与对象摘要 |
| 操作按钮 | 饱满胶囊、清晰窄边光与轻微凸面 | 可点击操作和选中块 |

文档、证据、比较表、表单使用稳定实色或高不透明度底面。玻璃不能降低必要内容的可读性。

### 6.2 光线与阴影

- 主光来自左上，环境色偏暖灰，右上融入低饱和蓝灰。
- 边缘反光窄而克制，不使用粗白描边和整圈强光。
- 同时保留小范围接触阴影和外围柔和扩散阴影，色相偏蓝灰，不用厚重黑影。
- 表面有内部明暗变化，但不添加紫、粉、青色虹彩。
- 现有控件 blur 约 10px、面板约 14–16px 可作起点；不能将所有嵌套层都叠加 blur。
- 不支持 backdrop-filter、用户选择减少透明度或背景复杂时，回退为白色实面。

**技术表述必须准确：本项目是背景模糊、渐变高光、倒角与阴影模拟；没有实现真实光学折射。** 普通 backdrop blur 不称为真实折射。

## 7. Before / After 统一对比语言

适用于 Studio 首屏 Round1 集成、局部流程、场景变化说明和打印。

### 7.1 主图例

| 类型 | 定义 | 视觉规范 | 证据约束 |
|---|---|---|---|
| **保留 Retained** | 工作及关键语义延续 | 白底、灰色实线、文字标签 | 不代表人/工具/执行时机完全相同 |
| **删除 Removed** | 有依据地取消原活动 | 灰色虚线轮廓、“删除”标签及减号图标；正文仍可读 | 不能仅因划线或从某泳道消失判断删除 |
| **增强 Enhanced** | 原活动保留但输入、准备、透明度或协作有所改变 | 浅蓝底、深蓝强调边、“增强”标签 | 详情明确增强了哪个字段、动作或交接 |
| **新增 Added** | 原流程中没有对应活动，Target 明确引入 | 蓝色标识带、加号图标、“新增”标签 | 不能把全部 Target 节点都标新增 |
| **待确认 Unconfirmed** | 来源或映射不足以可靠判断 | 中性点线、“待确认”文字 | 保留原位置与歧义，不猜测结论 |

“移交 / 拆分 / 合并 / 改序”作为附加关系标签，描述变化机制，不替代四类主图例。一个节点涉及多种变化时在详情列明各个对应关系，不强行塞入单一颜色。

删除节点可在 After 的对比叠层或清晰变更清单中查看，不假装它仍在目标执行路径中。Before 和 After 的实际连线与删除参照层要区分。

### 7.2 选择不是变化分类

选中节点用外层焦点/选择轮廓和详情标题表达，不能覆盖节点本身的新增/增强标识。流程连接线保留流程语义，变化类型主要编码在节点与对照说明，不改造箭头含义。

### 7.3 切换合同

- 使用真正的 Tab 语义：Before、After；同时只有一个选中项，关联对应面板。
- 切换保留语义节点、缩放与相近视野；一对多映射可明确展示相关节点集合。
- 无唯一对应节点时解释原因，不随意跳到图中央。
- Legend 在两种视图一致、持续可达；支持文字/图标，不只靠颜色。
- 流程支持 Fit、可读放大、合理平移；鼠标拖移不得吞掉普通点击。
- 默认不自动播放切换；切换不写业务状态。
- 打印保留类型文字和线型，不依赖蓝色打印效果。

## 8. 执行方式与业务状态分开

### 8.1 执行方式标签

统一采用：**Rule、Workflow、Deterministic Skill、Semantic Skill、Bounded Agent candidate、Human**。名称与来源映射继承 D4。

使用文字标签及同一图标家族。不要给六种执行方式分配六种鲜艳颜色；不要将 Workflow、Skill 和 Agent 全称为“Agentic”。一个工作可以包含多种执行方式。

- AI 准备材料与人的正式决定使用不同标题、容器与记录标识。
- 候选 Agent 明确“候选 / 未部署”；预编制示例不演成实时模型运行。
- 解释 Why / Skills 的内容放在场景或 Operating Model，Product 首层展示可用成果。

### 8.2 业务状态

| 状态 | 必须同时表达 |
|---|---|
| 需要处理 | 当前角色可做的具体动作 |
| 处理中 | 有实际开始依据，不是打开页面即开始 |
| 等待 | 等谁、等什么、由谁跟进；正常等待不是失败 |
| 受阻 | 哪个动作前置不满足；不推断整案全停 |
| 未知 | 未知对象和确认路径，不填零、不静默删除 |
| 已完成 | 完成的局部范围与产物，不等于全案准入 |
| 不适用 | 当前范围下有依据的不适用，而不是未展开 |
| 过时 | 哪项输入变化、需要重审什么；保留旧记录 |

Owner、next actor、waiting on 各自有意义，不合成一个“负责人”。时间健康与业务状态分开；无 SLA 不显示 SLA 超时。

## 9. 组件与完整交互状态

### 9.1 按钮

一个当前工作区只有一个最突出主动作；保存草稿、查看来源、返回为次级。正式决定不预选成功结果。

| 状态 | 外观 / 行为 |
|---|---|
| 默认 | 静止、边界清楚、文案可读 |
| 悬停 | 细指针设备上表面轻微上浮，边光稍增强 |
| 按下 | 表面降低并轻微压缩，阴影同步收紧，文字不缩放 |
| 松开 | 一次克制回弹，随后静止 |
| 键盘焦点 | 清晰连续轮廓，建议 2px + 3–4px offset；深色背景使用可见反差 |
| 选中 | aria 状态、文字/图形与选中块一致，不仅颜色变化 |
| 禁用 | 禁用语义、附近可读原因；没有悬停光效，不依赖 hover 解释 |
| 提交中 | 防重复操作，表达真实保存状态，不伪造模型进度 |
| 成功 / 失败 | 持久结果回执或就地错误；失败保留输入，不只有瞬时 toast |

### 9.2 Tabs / Segmented control

选中玻璃块连续滑动，标签保持不动。长度按实际文字测量，中文和英文不得被裁切。减少动态效果时直接切换，保持焦点与选中语义。

使用 `tablist / tab / tabpanel` 时支持方向键与 Home/End；若是普通切换按钮组，使用相应 pressed 状态，不混合两套语义。

### 9.3 输入与表格

- Label 始终可见，placeholder 不代替 label。
- 输入使用乳白/白底，错误就地显示；窄屏输入字号 16px。
- 比较表逐字段展示输入、来源/精度、用途、未知与候选判断。
- 必要依据不能被 Customize 隐藏。
- 只读字段与可编辑字段外观不同；“已查看”不转成“已评估”。
- 表头与单元格有真实语义，横向滚动有可读提示和键盘入口。

### 9.4 Dialog / Scenario panel

中央大面板保持标题、关闭和返回来源。内容较长时使用同一主滚动容器；不叠加第二层资料弹窗。

打开后合理移入焦点，关闭后回到来源场景卡；焦点不得被粘性工具栏遮挡。未保存离开显示 **Save draft / Discard / Stay**；保存失败不离开。

## 10. Persona 与场景图片系统

### 10.1 Persona 标准卡

每个 Persona 必须有：

1. 合成展示名 + 角色；保留稳定角色 ID，Person T 不被另一个名字替换。
2. 一张人物画像；建议主档 4:5，列表使用受控 1:1 裁切。
3. 工作背景、职责、目标和所见工具/资料。
4. Pain points、Expectations、主要交接与等待。
5. 与 Hero case 的关系及来源状态。

人物姓名和图像明确为合成。PPT 后两页可支撑痛点/机会，但未明确归属于某人的部分标为角色推导，不伪造访谈引语或个人经历。

### 10.2 场景标准卡

每个场景有独立情境图，建议 16:9；图片展示具体工作、资料或交接，不是同一张人物照重复裁切。卡片展示：业务标题、人物/角色、目标、当前阻碍或机会、打开场景入口。

相同场景在多个角色中出现时，沿用同一场景 ID，可选择角色特定裁切/辅助图，但不变成多套案件事实。

### 10.3 图像风格

- 近真实的编辑式机构工作情境，光线自然、低饱和，服装和环境安静。
- 不使用交易大厅霓虹、机器人、悬浮代码、发光大脑或夸张庆祝。
- 不把人物塑造成“有疑似命中所以危险”的形象，不以外貌编码风险。
- 不在生成图片中放关键可读字段；业务文字用 HTML 清晰排版。
- 不把合成文档图像当作身份证件、银行证据或已核实的来源。
- 图像使用范围、来源、revision、locale关联、alt、裁切焦点、状态进入既有媒体清单。

每个 Persona / Scenario 的图片覆盖率必须可核对。缺图时使用明确文字 fallback 保持操作，但该图片项仍记缺失，不能宣称视觉完成。

## 11. 场景、产品与 Research 内容模板

### Scenario 展开顺序

情境图与 Hero moment → Journey / Role / Process 定位 → Before/After 体验 → Pain/Opportunity → 局部流程与人机分工 → 字段级对照 → 对应产品设计图 → 进入真实任务 → 讨论问题与研究依据。

Before/After 比较目标、行为、所见、等待、交接、输入输出和影响。不用“After 更智能”代替明确差异。

### Product 固定核心

当前任务与案件定位、紧凑进度/时间、必要依据、下一动作与关键提醒不可移除。完整历史、非必要资料、完整依赖图可按需展开。

人物情境图片主要服务 Studio；Product 的主要视觉是实际证据、比较表、关系图和可操作工作区，不在决定区域放营销大图。

### Research 卡片

固定五段：Company context → Org/department → Customer journey → 对 CTT 的启发 → 本次采用位置。附原始来源、日期、证据类型、Adopt/Adapt/Avoid 和类比限制。

真实公司案例、供应商主张、行业标准、设计假设分别标识。采用位置必须连接具体场景/字段/页面，不只写“给我们启发”。

## 12. 动效规范

动效只表达高度、受力、选择、定位和交接，不表达未经确认的工作完成。

| 效果 | 参数起点 / 限制 |
|---|---|
| 常规交互 | 180–220ms；沿用 `cubic-bezier(.2,.75,.25,1)` |
| 按下 | 约 90ms；仅表面层压缩 |
| 松开回弹 | 约 320–400ms；一次，不持续振荡 |
| 悬停上浮 | 不超过 2px |
| 指针倾斜 | 规范上限约 1°，仅 fine pointer；图表/证据/文字不倾斜 |
| 高光跟随 | 局部、柔和、低幅度；离开即恢复静态 |
| Tab 选中块 | 约 220–280ms；轻微拉伸只作用于表面 |
| 空闲 | 完全静止，不呼吸、不闪烁、不自动滚动 |

文字和图标位于独立稳定层，不能参与 blur、倾斜、拉伸或形变。形体、反光和阴影变化同步，不能物体下降而阴影变大。

`prefers-reduced-motion` 下关闭倾斜、位移、拉伸、回弹和自动播放；保留静态边界与状态反馈。触屏通过按下/松开反馈，不依赖 hover。

声音与动画偏好独立。实际 Product 默认安静；媒体进入人工关卡、打开产品、离开页面或打印前暂停。播放时长不是业务办理时间。

## 13. 响应式、可访问性与打印

### 响应式目标

- ≥1200px：宽流程画布、Journey 定位和双栏任务工作区。
- 768–1199px：减少非必要并列区域，详情可下置；保留主要图与操作。
- <768px：单列内容，人物/场景图片不丢失；复杂流程仍可放大查看，不缩成不可读缩略图。
- 只在图/对照表等必要区域横向滚动，不让整个页面意外横向溢出。

### 项目可访问性验收目标

- 普通文字对比度至少 4.5:1；大字和必要非文字控件边界至少 3:1，按实际背景测量。
- 所有主路径可用键盘；焦点可见且不被覆盖。
- 颜色不是唯一编码；缩放、减少动态效果、缺图仍能理解。
- 图片有有意义 alt；装饰图不重复朗读标题；复杂流程有可访问的文本/列表等价内容。
- 图中选择节点能通过列表或键盘定位，不要求只能精准拖移点击。
- 200% 文本/页面缩放须走查；完整辅助技术支持未经实测不得宣称通过。

以上是目标，不是本版文档已完成的认证。

### 打印

白底、深色文字、无玻璃/动效/悬浮阴影。打印完整选择内容而非 viewport；Before/After 可各占适当页面并重复 legend。字段表重复表头，避免节点/文字被裁断。

保留合成标记、来源、版本、选择范围和必要业务边界。按当前角色过滤，不能为打印绕过权限。
